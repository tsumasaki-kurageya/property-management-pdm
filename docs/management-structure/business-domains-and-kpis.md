# 役割別の業務領域と主要KPI v1.0

## 1. 目的

本書は、オーナー、アセットマネジメント（AM）、プロパティマネジメント（PM）、ファシリティマネジメント（FM）、ビルメンテナンス（BM）について、各役割が担当する**業務領域**と、成果・リスクを判断する**主要KPI、KRI、評価観点**を共通の構造で整理する正本である。

同じ建物、設備又は事象でも、役割ごとに管理対象、意思決定、評価期間及び成果指標が異なる。本書はその違いを比較可能にし、後続の責任分界、上位業務とBM業務の接続、代表シナリオ及びGitHub Pages実装で安定IDを再利用できる状態を作る。

上位役割は業務領域レベルまでを対象とし、AM・PM・FM等の詳細業務カタログは作成しない。BMは[ビルメンテナンス業務カタログ v1.5](../building-maintenance-business-catalog.md)のBM-01〜BM-18、181業務を正本として参照し、既存IDを変更しない。

## 2. 適用範囲と前提

### 2.1 役割は会社ではなく機能として扱う

本書の役割は法人名又は部署名ではなく、案件内で担われる業務機能を表す。一つの組織が複数機能を兼ねる場合、一つの機能が複数組織へ分割される場合、AM又はPMが独立して存在しない場合がある。

役割の配置は、[オーナー・AM・PM・FM・BMの役割・業務レイヤー定義](./roles-and-layers.md)に従い、主目的、管理対象、意思決定範囲、成果物及び計画期間で判定する。

### 2.2 記述区分

| 区分 | 本書での扱い |
|---|---|
| 根拠定義 | リポジトリ内の正本又は行政機関・業界団体・専門団体の公開資料で確認できる内容 |
| 標準モデル | 複数の根拠を接続し、本プロジェクトで共通利用するために整理した業務領域、指標及び接続関係 |
| 変動事項 | 所有・利用形態、契約、権限規程、会計方針、法令、建物用途等により案件ごとに決める事項 |

本書の業務領域分割、KPI候補及び役割間接続は標準モデルである。個別案件では契約書、仕様書、賃貸借契約、権限規程、会計方針、法令及び行政運用を優先する。

### 2.3 KPI、KRI、評価観点

| 区分 | 定義 | 例 |
|---|---|---|
| KPI | 目標に対する成果又は業務遂行を定量的に追跡する指標 | NOI、稼働率、作業実施率、利用者満足度 |
| KRI | 将来損失、停止、法令違反等のリスクの増大を早期に把握する指標 | 更新バックログ、重大是正滞留、空室期間、重要設備停止リスク |
| 評価観点 | 単一の数値目標にすると誤解を招くため、複数の定量・定性情報で判断する事項 | 保有目的適合性、投資の価値寄与、技術提案の実行可能性 |

KPIは高ければ常に良いとは限らない。費用削減と品質・安全、稼働率と賃料条件、作業実施率と作業有効性等、相反又は補完する指標を組み合わせて評価する。

## 4. 業務領域IDの採番

- オーナーは `OWN-xx`、AMは `AM-xx`、PMは `PM-xx`、FMは `FM-xx` とする。
- IDは役割別の業務領域を識別し、詳細手順、成果物、会社又は部署を識別しない。
- 表示順や組織階層を意味せず、領域の意味が同じ限りIDを維持する。
- 分割・統合で廃止したIDは再利用しない。
- BMは既存の `BM-01`〜`BM-18` を継続利用し、181の詳細業務IDを変更しない。

## 6. 財務用語のガイド内定義

本節は役割間の会話を一致させるためのガイド内定義であり、会計基準、税務又は投資契約の完全な標準化を行うものではない。実際の計算では、対象費目、期間、配賦、税・借入・準備金等の扱いを指標定義書で固定する。


| 用語 | 本ガイド内の定義 | 主な利用者 | 注意事項 |
|---|---|---|---|
| 物件運営収入 | 賃料、共益費その他、対象物件の運営から得る収入。本書では集計範囲を案件ごとに固定する。 | AM、PM | BM会社の受託売上とは別。 |
| OPEX | 物件・施設を日常的に運営・維持するための経常的支出。本書ではBM委託費、光熱費、保険、税、日常修繕等のうち案件で定めた費目を含む。 | AM、PM、FM | 会計・税務上の費目区分を優先し、技術的な「修繕」名称だけで判断しない。 |
| CAPEX | 資産の取得、更新、機能向上、耐用年数延長等を目的とする資本支出。 | オーナー、AM、PM、FM | 資本計上の可否は会計方針・税務・契約に従う。大額であることとCAPEXであることは同義ではない。 |
| NOI | 物件運営収入から、物件の管理運営にかかる費用を控除した純営業収益。 | AM、PM、オーナー | 減価償却、支払利息、法人税、CAPEX等の扱いを指標定義書で固定する。BM会社の利益ではない。 |
| NCF | 本書ではNOIに敷金等の運用益等を加え、CAPEXや案件で定める投資関連支出を控除した純キャッシュフロー。 | AM、オーナー | ARESの説明を基礎とするが、仲介費・準備金等の扱いは案件で明示する。 |
| IRR | 投資期間のキャッシュフローの現在価値と初期投資額が一致する割引率。 | オーナー、AM | レバレッジ前後、税前後、投資期間、売却価値、追加投資の前提を明示する。 |
| 資産価値・NAV | 個別資産の評価額、又は保有資産評価額から負債等を控除した純資産価値。 | オーナー、AM | 個別物件の評価額とファンド・法人のNAVを混同しない。 |
| BM会社の売上 | BM会社が契約作業、追加作業、修繕工事等の提供対価として認識する収入。 | BM | 同じ支出が物件側ではOPEX又はCAPEX、BM側では売上となり得る。 |
| BM会社の原価・粗利 | BM会社が受託業務のために負担する労務費、材料費、外注費等と、売上との差額。 | BM | 物件NOI、物件OPEX差異とは別主体・別目的の指標。 |

### 6.1 BM会社の売上・原価と物件側指標の区別

同じ修繕工事でも、会計主体と評価目的が異なる。

```text
物件・資産側
  支出 → OPEX又はCAPEX
  影響 → NOI、NCF、IRR、資産価値

BM会社側
  受託対価 → 売上
  実施コスト → 労務費、材料費、外注費等の原価
  影響 → 粗利、契約採算
```

したがって、BM会社の売上増を物件側の財務成果とみなさず、物件側の費用削減をBM業務の成果とみなさない。品質、安全、設備状態、利用影響及び将来リスクと合わせて評価する。

### 9.1 中央熱源設備が故障し、修理又は更新が必要になった

技術的には同じ故障でも、各役割が判断する対象は異なる。

| 役割 | 主な判断・行為 | 主に見る指標・評価観点 |
|---|---|---|
| オーナー | 重大CAPEXの承認、保有方針・リスク受容との整合 | 投資額、重大リスク、資産価値、長期キャッシュフロー |
| AM | 修理・更新・繰延の投資効果と保有期間内の最適時期を評価 | NCF、IRR、CAPEX予算、資産価値、更新繰延リスク |
| PM | テナント影響、物件予算、工期、発注・検収を統括 | NOI影響、予算差異、停止時間、苦情、委託先履行 |
| FM | 事業継続、室内環境、代替運用、将来性能を評価 | 事業影響時間、快適性、BCP、エネルギー、利用者満足 |
| BM | 原因診断、応急復旧、修繕・更新案、施工条件を提示・実行 | MTTR、再発率、設備健全度、安全、作業原価・粗利 |

### 9.2 法定点検で重大な不適合が判明した

「BMが直す」だけでは、義務主体、費用、リスク受容及び対外説明の判断を表現できない。

| 役割 | 主な判断・行為 | 主に見る指標・評価観点 |
|---|---|---|
| オーナー | 重大な法令・安全・信用リスクの対応方針と受容可否を決定 | 重大度、行政・対外影響、是正滞留、委任統治 |
| AM | 資産・ポートフォリオ価値、予算、売却性への影響を評価 | 資産価値、CAPEX、KRI、保険・集中リスク |
| PM | 義務主体・契約境界、是正発注、テナント・行政連絡を統括 | 是正期限、予算、証跡、委託先履行、テナント影響 |
| FM | 人命・事業・利用継続への影響と暫定運用を評価 | BCP、利用不能、代替策、利用者周知 |
| BM | 不適合を検出・速報し、安全確保、技術評価、是正作業と証跡作成を行う | 未実施・不適合、是正完了、作業安全、記録完全性 |

### 9.3 長期空室が増え、改修又は用途見直しが必要になった

空室はPMだけの問題ではなく、投資、施設需要及び現場保全へ異なる影響を与える。

| 役割 | 主な判断・行為 | 主に見る指標・評価観点 |
|---|---|---|
| オーナー | 保有継続・用途転換・売却等の戦略判断 | 資産価値、投資成果、保有目的適合性 |
| AM | リーシング投資、改修、売却等の資産運用シナリオを比較 | NOI・NCF・IRR、空室リスク、CAPEX、価値変動 |
| PM | 募集条件、テナント維持、物件収支、改修・内覧を管理 | 稼働率、空室期間、成約、賃料、テナント満足 |

## 11. 後続成果物への接続ルール

- 責任分界では、業務領域IDを起点に、起案、技術評価、費用査定、承認、実行、確認、報告を割り当てる。
- RACIとは別に、法的義務、費用負担、リスク受容、緊急停止権及び最終決定権を管理する。
- BM接続マップでは、上位領域とBM-01〜BM-18を、要求、委託、承認、実績報告、異常報告、技術提案等の接続種別で結ぶ。
- 指標は名称だけで接続せず、ID、管理対象、集計単位、期間及び定義版を保持する。
- GitHub Pagesでは、オーナー→AM→PM→BMを固定的な会社序列として表示せず、PM系とFM系が並列にBMへ接続し得ることを示す。

### 13.3 根拠と標準モデルの区別

- 外部資料が示すAM、PM、FM、BMの定義及び既存正本の役割境界は根拠定義である。
